# Parent discovery and disposable serving qualification

This is source acceptance, not Stack promotion or permission to adopt a site.
The component tooling is excluded from the default Stack payload. The existing
retirement lock and recovery artifacts remain unchanged.

The 19 component tests pass, including three fresh WordPress installations.
Native theme discovery, metadata, template and pattern loading use the selected
parent generation while preserving the physical child. Core overwrite, uninstall,
delete and theme-switch paths are guarded. A substituted parent view is refused.

The browser fixture proves actual warm-cache responses, old/new coherent parent
and plugin pairs, immutable asset bytes and MIME, retained old HTML and rollback
with OPcache enabled. Its serving policy is test code, not provider configuration.
MRN QA also passed source, REST, public browser, axe, timing and CWV checks against
the same temporary loopback server. The sample page had no measured INP. No
real fleet layout or independent child release loader is qualified by this test.

The initial QA call unexpectedly invoked the engine's broad, read-only development
parity audit. It found seven version/readiness mismatches and made no site changes.
The retained isolated report is a second run with that hook excluded and SSH
blocked. The earlier report remains in the external artifact directory for audit.
Do not interpret either report's generated success label as fleet readiness.

Remaining gates are listed in `status.json` and the component tooling README.
External build, recovery and Git receipts are under
`MRN-release-artifacts/2026-10-05-component-theme-qualification`.
