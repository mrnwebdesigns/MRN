# ACF nested field validator defaults

Parent theme 1.5.2 completes late-injected nested ACF text and number fields
with the blank limit defaults ACF normally supplies while initializing those
types. This prevents ACF PRO 6.8.10 from reading undefined `maxlength`, `min`,
or `max` keys when it validates MRN builder fields. Authored limits are checked
with `array_key_exists()`, so explicit values—including zero—remain unchanged.

The shared finalizer still preserves field keys and names, saved values,
repeater/flexible/clone structures, select behavior and frontend rendering. It
does not patch ACF vendor code, suppress warnings, change content, or address
the separate historical Customizer response.

## Evidence and validation

- The Gloves investigation correlated two Home-page save windows with 180
  undefined-`maxlength` and 12 undefined-`max` warnings per window. Read-only
  validator probes reproduced both warnings from live MRN-generated fields.
- The focused PHP regression covers missing text/number defaults and preserves
  explicit zero limits alongside existing recursive select-field coverage.
- The runtime regression resolves the actual nested
  `field_mrn_hero_two_column_split_min_height` and
  `field_mrn_content_grid_items_links_icon_gap` definitions, then calls ACF's
  real text and number validators without saving content.
- The MRN staged commit gate, static security checks, PHP 7.4–8.3
  compatibility, PHPStan, Semgrep and the complete parent-theme PHP harness
  pass. Runtime API, editor and public checks remain deployment gates.
