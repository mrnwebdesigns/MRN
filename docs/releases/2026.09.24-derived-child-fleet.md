# Exact derived-child Fleet preparation

Release: `2026.09.24-derived-child-fleet`.

This release removes the false all-or-nothing child-theme restriction from the
full Stack Fleet path without widening its write targets. A site can qualify
when its active template is exactly `mrn-base-stack` and its active stylesheet
is either the stock child or one exact site-specific child attested by Deployment
Agent `0.2.4`.

## Safety contract

- Generate a separate plan and rollout ID for each exact active stylesheet with
  `build-mainwp-stack-release.py --site-stylesheet <slug>`.
- Reject an empty, unsafe, parent-equal, or mismatched stylesheet.
- Package and update only the immutable Stack components and canonical parent.
  Never package, target, rename, activate, or overwrite the child theme.
- Require MainWP Operations API `0.9.5` and the exact Deployment Agent `0.2.4`
  version, tree hash and file count before full preflight.
- Keep renamed-parent, clone-style and ambiguous theme shapes outside schema 2.
- Preserve the normal exact-site authorization, fresh remote database backup,
  two-step confirmation, runtime readback and user-visible QA gates.

## Target implications

- Gloves Online and Trilliant use the stock child contract but must first have
  the exact agent prerequisite and managed-credential readiness required by
  preflight.
- Doster's site-specific child is now representable by an exact one-site plan;
  the plan must use the freshly read active stylesheet and still requires the
  agent and every required Stack plugin to be present and active.
- Agent upgrades remain upgrade-only. Installing the agent where absent is a
  separate prerequisite-seeding write requiring explicit authorization and its
  own verified backup receipt.

This preparation does not deploy the Dashboard controller, install or update a
child-site plugin, or apply a Stack release to any site.
