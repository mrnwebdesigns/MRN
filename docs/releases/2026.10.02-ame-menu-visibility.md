# AME menu visibility release

Release: `2026.10.02-ame-menu-visibility`.

## Change

Public Security Hardening `0.4.3` respects the final menu produced by Admin
Menu Editor. Previously, the shared MU component restored Advanced/Public
Security after AME had removed it for Shop Manager. The reassertion callback
now returns once AME has completed its menu replacement. The native fallback
without AME and existing capability checks remain unchanged.

No new menu, role capability, database migration, or child-theme workaround
is included. The existing standalone Broken Links entry remains available.

## Scope and verification

- Source PR: https://github.com/mrnwebdesigns/MRN/pull/167.
- Regression checks cover AME-hidden menus, administrator custom placement
  and labels, unrelated Advanced groups, standalone Broken Links, denied
  capabilities, and the native fallback. The hidden-menu regression fails
  against the old source and passes with the fix.
- Component MRN QA passed static, WordPress, security and API-surface checks.
- Full release-mode MRN QA passed on isolated WordPress with the exact changed
  component: browser smoke, API runtime, axe accessibility, page timing, Core
  Web Vitals, and all component static/security checks. Login, logout, reset,
  registration and reauthentication HTTP checks cover root, subdirectory and
  split home/siteurl installations.
- Fleet-wide Config Helper parity is outside this one-site menu repair; the
  exact Gloves component hashes and deployment-agent readiness are checked
  through MainWP before rollout.
- Merged-source promotion audit identifies Public Security Hardening as the
  only required component changed since `2026.10.01-acf-field-defaults`.
