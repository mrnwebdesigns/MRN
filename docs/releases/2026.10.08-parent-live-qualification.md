# Parent-only Nexcess Live qualification candidate

The owner authorized continued shared Stack work and required CAPTCHA to work
without WooCommerce. CAPTCHA PR #7 adds independent real WordPress qualification
with WooCommerce and WPForms absent; it changes no production runtime code and
does not advance the qualified 0.1.4 bootstrap default.

The parent transport previously rejected every Live target. This source adds
an explicit **Nexcess Live qualification candidate** using the existing
Cache Enabler exact-URL adapter. CloudPanel Dev remains supported. Other Live
providers, automatic adoption and a native Dashboard parent installer remain
unsupported by this route. No target is enrolled or deployed by this commit.

## Reviewed plan and write gates

- Resolve the exact production URL through MainWP and narrowly sync it. The
  reviewed evidence must come from `wpcontrol.mrndev.io`, identify that URL and
  site ID, and be less than 15 minutes old.
- The candidate requires `environment: live`, `host_provider: nexcess`, an
  explicit site-owner `*.nxcli.io` SSH endpoint, `backup_provider: updraft`,
  `qualify_live: true` and `exercise_rollback: true`. A hostname/environment
  change alone cannot select Live.
- Require the actual WordPress environment to be `production`, canonical
  `mrn-base-stack` parent, and the exact independent child. Record source,
  package checksum, physical root, preserved child/parent inventories, existing
  pointer, private control checksum and other Stack bytes. An ordinary physical
  child uses explicit `child_state: null`; a released child uses its exact
  private state. Existing control-code drift requires separate qualification.
- Parent state is private, site-isolated, outside the WordPress root, and on
  the same filesystem. The selected directory is
  `/home/<site-owner>/private-backups/mrn-parent-deploy/live/<sanitized-host>`.
- Read-only preflight discovers public and already-cached HTML routes through
  the existing helper. Bind that exact ordered set as `html_urls` in the plan.
  Both operator and destination reject a changed scope before release writes.
- Create and verify a fresh labeled, remote database-only Updraft backup before
  transferring control code or staging assets. The destination independently
  verifies the same receipt before provisioning. Ordinary retention applies.
- Stage one source/checksum-bound immutable parent; preserve public parent,
  child, old asset URLs and unrelated Stack code. Reuse the existing private
  store, exclusive parent/child writer locks, compare-and-switch pointer,
  journal and recovery. Do not replace an existing control runtime silently.

## Public, cache and recovery proof

The early loader emits a request-pinned `mrn-parent-release` HTML meta element.
Unlike PHP-only headers, that marker survives static HTML caching. It names the
artifact selected before the theme loads and never rereads the active pointer
during rendering. It has no visible page content.

The controller refreshes only the reviewed Cache Enabler HTML URLs using
`clear_page_cache_by_url(..., 'page')`; it does not purge objects, transients or
static assets. The URL set travels on stdin to avoid environment/argument size
limits. Every sampled normal URL must return the selected marker on first and
warm responses; a contradictory header, duplicate/missing/stale marker or
partial refresh fails. The existing public verifier also checks exact manifest
asset URLs and decoded SHA-256 bytes. An edge cache still serving an older body
blocks qualification; this source does not widen invalidation to bypass it.

Rollback and reactivation are mandatory in this qualification route. Returning
to the legacy parent must remove its selected marker from fresh affected HTML;
returning to an earlier managed parent must select that exact earlier artifact.
Retained old HTML and immutable dependencies remain available. A failed recovery
remains `recovery-required`; no database restore is used to undo parent code.

Source and disposable runtime tests do not qualify a real provider. Acceptance
still requires the exact production canary, public cache behavior, preserved
child/parent inventory, browser/editor/accessibility/API/performance checks,
backup and rollback receipts. The owner has not authorized that site write.
Trilliant Dev application remains held; no Dev speed tests are part of this work.

Reference: the official [Cache Enabler source](https://github.com/keycdn/cache-enabler/blob/master/inc/cache_enabler.class.php)
provides the URL-scoped method. Provider-specific serving and cache behavior
must be checked on the named target.
