# Config Helper startup release candidate

Release: `2026.09.25-config-helper-startup-fleet`.

Config Helper `0.1.66` removes builder-layout discovery from lightweight settings
reads. A content-type visibility check now reads stored values and defaults;
builder allow-lists, settings rendering and saves explicitly request normalized
layout settings. Public method signatures, legacy migrations, initialization
guards and stored values remain compatible. ACF registration stays enabled.

This is the only component delta from `2026.09.25-content-filters-fleet`.
Parent theme `1.5.0`, Character Count `1.1.9` and all other component trees are
preserved. Character Count and further performance work remain separate.

## Qualification

The focused suite passes 738 assertions across frontend, admin, REST, AJAX, cron
and CLI contexts. Real WordPress/ACF integration and authenticated browser
checks pass on separate standard and WooCommerce local fixtures, including ACF
save/reload, visibility settings saves, allow-lists, frontend output, REST,
heartbeat AJAX, and settled Orders/Customers screens. MRN component release QA
passes on both named local runtimes. Advisory PHPStan symbol findings and
inapplicable standalone QA rows are disclosed in the reports.

Final uninstrumented local HTTP medians for Woo Orders changed from 965.3 to
360.8 ms and Customers from 945.7 to 333.9 ms (10 samples/version/route).
Discovery calls fell from 279 to zero on both documents. Standard editor and
frontend, and Woo settings, had slower medians in this run. These are PHP
cli-server document TTFB measurements, not production PHP-FPM, full browser
waterfalls or fleet-wide gains. CLI results are reported separately.

See `reports/config-helper-startup-2026-09-25/RESULTS.md` for all routes,
variability, raw observations, limitations and compatibility evidence, and
`docs/MRN-CONFIG-HELPER-STARTUP.md` for the dependency trace.

## Deployment state and remaining gates

No remote site has been changed by this preparation. The selective canary plan
updates only Config Helper against each site's signed immutable baseline; it
does not deploy the cumulative parent-theme candidate or relabel the site as a
new full Stack release.

Proposed canaries are Trilliant development followed by Gloves production.
Each requires a fresh exact-site Fleet preflight, reviewed precondition hash,
verified remote database-only backup, explicit execution confirmation, and
signed runtime/public readback. Canary editor/save checks and comparable real
web-request measurements precede any approved cohort expansion. A rollback
uses the exact prior version/tree, a fresh backup and separate confirmation.

The release remains a candidate until the declared deployment targets pass
those gates. Source merge, local measurements and deterministic packages alone
do not establish remote or fleet performance.
