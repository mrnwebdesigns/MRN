# 2026.09.24 Admin Field Assets Fleet Release

This release versions and packages the completed admin asset-loading work for
guarded Fleet rollout. It does not deploy the MainWP controller or change a
child site by itself.

## Release scope

- `mrn-base-stack` `1.4.3`
- `mrn-shared-assets` and its loader `0.2.1`
- `mrn-config-helper` `0.1.64`
- `mrn-acf-character-count` `1.1.9`
- Dashboard-only `mrn-mainwp-operations-api` `0.9.6`

Config Helper is platform-required and is included in the immutable full Stack
lock. Its exact release also remains available through the selective Stack
plugin path. Character Count remains an optional integration: Fleet may update
it only when fresh inventory proves it is already installed. Missing Character
Count installations require separate authorization and are never inferred from
bootstrap or catalog membership.

## Qualification evidence

The implementation passed 154 focused regression assertions and browser checks
across ten local admin states. An empty ACF screen omitted fourteen helper
elements, including approximately 104.5 KB of inline configuration, while real
editor rows, layout and icon controls, cloned counters, dynamically added ACF
fields, and save/reload behavior remained intact. No new JavaScript exceptions,
failed assets, or axe findings were observed.

Each standalone release passes its full MRN plugin QA. The Stack candidate must
also pass the complete unit suite, parity audit, release-mode MRN QA, immutable
lock validation, deterministic package verification, and candidate promotion
audit before it is called production-ready.

## Rollout gates

1. Deploy MainWP Operations API `0.9.6` to `wpcontrol.mrndev.io` only after an
   explicit Dashboard authorization and a verified remote database-only backup.
2. Resolve each child site by exact URL, perform a fresh targeted MainWP sync,
   and re-run qualification against the final immutable release lock.
3. Upgrade or seed the Stack deployment agent only through a separately
   authorized, backup-gated prerequisite plan.
4. Build one exact site plan and preserve the active child theme. The child
   theme is never included in or overwritten by the Stack package.
5. Before every site write, create and verify a fresh labeled database-only
   Updraft backup at the configured remote destination.
6. Stop on any preflight, backup, checksum, active-state, version, runtime,
   browser, or public readback failure.

Cookie Consent remains on its separately canary-gated optional Fleet record;
this release does not promote the newer Cookie Consent source or change its
deployment authorization.
