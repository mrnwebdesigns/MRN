# ACF builder editor performance

Unused MRN flexible-content templates now render their controls when an editor
selects the layout. Saved rows and ordinary repeater templates still render on
the initial request. The adapter uses ACF's native renderer and row creation;
field definitions, storage keys, saved values, defaults and allowlists remain
intact. It applies to Classic Editor post screens and the Stack 404 options editor.

The layout endpoint requires the native field nonce and permission to edit the
target post (or `edit_theme_options` for the exact 404 options namespace),
validates the input path and rejects unavailable layouts. Saving
waits for pending requests. Failed requests remain retryable without adding
empty rows. Completion rechecks per-layout limits, and reusable-block conversion
waits for initialized controls before copying values and removing the reference.
Native media dependencies are enqueued for initially empty editors.

## Platform qualification

On `https://platform.localhost`, the settled editor DOM contained:

| Page | Previous ACF controls | Candidate ACF controls |
| --- | ---: | ---: |
| Home | 4,642 | 180 |
| Services | 4,236 | 410 |
| 404 options | 163 | 10 |

These are browser control counts, not metadata-row counts or request-time
measurements. Native addition, nested layouts, duplication, drag reorder,
save/reload, reusable selection, conversion with heading/rich-text readback,
media selection and save-during-load behavior were checked. Published page
content/metadata hashes remained unchanged. Owned fixtures were moved to Trash.

Focused PHP tests cover template suppression boundaries, cloned selectors and
field finalization. `node stack/themes/mrn-base-stack/tests/js/lazy-layouts.cjs`
checks request failures, retry, save guards, conversion completion and an
in-flight layout-limit race. MRN QA covers the source and local runtime; the
staged-tree commit proof is a separate requirement.

Runtime QA passed with inherited advisories. The automated accessibility smoke
reported zero interactive controls exercised beneath the existing demo overlay;
it is not full WCAG sign-off. Canonical full-theme PHPCS has three pre-existing
warnings in the unchanged ACF defaults test. Changed-file PHPStan cannot discover
an unchanged thumbnail helper; analysis with that dependency included passes.

## Follow-up performance repairs

Empty public Hero and After Content renderers now avoid their derived field
catalogs when the persisted value is empty and no custom ACF behavior can supply
content. Platform's empty render added zero definitions instead of 2,987.
The conservative fast path falls back for previews, revisions, defaults, cached
values, alternate field references and unrecognized value/definition hooks.
Callback names are deliberately explicit: an unknown extension retains native
behavior. These counts measure field definitions, not HTTP response time.
Populated builder areas retain the existing rendering path. A loopback HTTP
comparison against the native fallback produced byte-identical Home, Services
and Contact responses. Whole-request registered definitions dropped from 5,349
to 3,328 on Home and Contact; Services remained at 2,362. Those HTTP totals include
other builder consumers, unlike the isolated empty-render count above. The
diagnostic PHP server is separate from OpenLiteSpeed, so its timings are not
reported as live-site latency gains.

Stack-owned repeaters now have a five-row ceiling, preserving tighter one- and
two-row limits. This replaces the earlier pagination/50-row editor policy.
Native editor controls and REST schemas expose the limit. Server validation
rejects oversized submissions, and an ACF pre-update guard checks the complete
submitted field tree before its parent or children can write metadata. The guard
also covers `update_field`, `update_sub_field`, and row-addition APIs. Direct SQL
and direct WordPress metadata writes remain outside this ACF policy.

Existing oversized values remain readable and editable through the native editor
and ACF update APIs, up to their saved count; reducing the count reduces that
allowance. No values are sliced or deleted. Reordering an existing layout retains
its nested allowance, while newly added layouts cannot inherit it. REST schemas
retain the fixed ceiling. Repeaters render without pagination under this policy;
large historical values still need content review. Flexible-content page sections
are not repeaters and retain their existing layout limits.

Platform's pre-change inventory found 17 saved repeater instances, a largest
count of two, and no authored values above five. Local integration checks cover
five/six-row saves, complete-field atomic rejection, nested/group/options fields,
API row additions, REST validation, legacy editing and row reorder. The native
FAQ editor refused a sixth row and saved/reloaded the fifth row successfully.

Earlier qualification also passed native 404 add/save/reload and oversized
25-row FAQ/55-row nested Stats preservation. Frontend ACF reads returned every
repeater row. Options AJAX rejects invalid nonce,
capability, target, input namespace and layout. Fixtures are local-only and
restore the exact 404 option snapshot before moving owned draft posts to Trash.

The follow-up MRN QA run passed static, security/API, browser, accessibility,
page-speed and Core Web Vitals checks against Platform. OpenLiteSpeed browser
measurements: Home LCP 812 ms, Contact LCP 1,236 ms, CLS 0 on both. Existing
advisories remain: eight unrelated parity targets, dependency discovery in
changed-file PHPStan (dependency-aware analysis passes), and the demo overlay's
zero interactive accessibility coverage. Release/license/rollout gates were
intentionally skipped for this feature qualification.

## Promotion boundary

This feature does not change the component version, catalog or release lock.
Promotion must assign coherent release metadata from clean merged source and
qualify the exact package on its approved targets. No remote site is updated by
this feature. The separate public After Content optimization is tracked in
MRN PR #200 and is not included here. It addresses request bootstrap work;
that work remains independent of this feature's empty-render shortcut and
editor payload changes.
