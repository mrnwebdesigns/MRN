# Content filters and editor guidance release candidate

Release: `2026.09.25-content-filters-fleet`.

## Included changes

- Parent theme `1.5.0`: additional category constraints alongside the existing
  tag/taxonomy filter, registered MRN content tokens in heading fields, and
  accessible Content Only / item-link guidance.
- Config Helper `0.1.65`: matching Content Types settings guidance and accessible
  descriptions for editable and locked switches. Existing registration, save
  authorization, file destinations, and content remain unchanged.
- The merged `mrn fleet update` command provides the guarded one-site path for
  registered platform-required standard plugins. It does not update themes,
  MU plugins, or shared runtime.

Feature changes remain separate commits: heading tokens (PR #122), category
filters (PR #123), theme guidance (PR #125), and Config Helper guidance (plugin
PR #7). Release metadata and the generated immutable lock are separate commits.
The unfinished guidance previously blocking promotion is now committed and
merged; this candidate does not rely on an exclusion exception.

## Qualification

Combined local checks cover real WordPress/ACF queries and saved data, seven
Reference Content browser scenarios, five category-filter browser scenarios,
16 heading-token assertions, cloned rows, anonymous filtered output, and
reachable PDFs. Config Helper's Content Types panel has accessible descriptions
for all 17 controls, including ten locked types, with no scoped axe WCAG A/AA
findings or JavaScript exceptions. The category controls also pass scoped axe.
WordPress's delayed login autofocus is awaited in the local category test
runner before entering disposable credentials.

MRN feature and release QA cover the named isolated local runtime, API health,
security, accessibility, browser smoke, and performance. The Stack Python
contract suite and the Fleet command's Node tests validate packaging and
orchestration contracts. Promotion candidate checks and deterministic package
verification must pass against the final merged lock.

Fleet parity warnings identify existing target-site differences. License,
site-owner write access, backup, and target-specific rollout readiness must be
qualified for each named site; local QA does not establish those remote facts.

## Using the candidate

Category filters and heading/editor changes are parent-theme changes. Request a
full Stack update through Fleet or an individually scoped site request. Resolve
the exact live parent and child themes, prepare the corresponding full-release
plan, and preserve the active child theme. Renamed-parent or clone-style sites
need their existing site-specific resolved deployment route.

Config Helper `0.1.65` is also registered as an immutable, upgrade-only selective
plugin release. Existing registered packages remain available for rollback.
It does not install on missing sites without separate authorization.

Every shared-runtime write still requires a fresh verified remote database-only
Updraft backup, the applicable deployment authorization, and exact runtime/public
readback. No Dashboard or child site is deployed by this candidate preparation.
