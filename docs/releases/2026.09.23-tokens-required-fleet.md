# Required Tokens Fleet preparation

Release: `2026.09.23-tokens-required-fleet`.

MRN Tokens is required on every MRN Stack site. Its earlier bootstrap entry
did not put it in the full Fleet package because the component catalog still
classified it as optional. This release aligns the required catalog entry,
immutable lock and full package with the bootstrap policy.

## Scope

- Include MRN Tokens `0.1.4` from its exact merged standalone source, with a
  deterministic package boundary and complete WordPress release metadata.
- Preserve existing `mrn_tokens_settings` values, shortcode/provider behavior,
  administrator-only settings and authenticated REST permissions.
- Retain the complete `2026.09.23-reference-content-fleet` baseline and archive
  that prior lock byte-for-byte. Its outstanding local/runtime qualification
  gates remain applicable; adding Tokens does not clear them.
- Keep the active child theme out of the full replacement package. Unmerged
  mobile-navigation and backup-policy task branches are not release inputs.
- No remote site or Dashboard changes are part of this preparation.

## Missing-plugin prerequisite, including Gloves Online

1. Resolve the exact intended site URL through MainWP and complete a fresh
   one-site sync. Never reuse a historical site ID.
2. Read the plugin inventory, deployment-agent status and Stack qualification.
   Confirm the actual parent/child theme and every required prerequisite.
3. If `mrn-tokens/mrn-tokens.php` is absent, use the exact standalone ZIP built
   from the Tokens commit/tree in this release lock. Obtain named-site
   authorization and a fresh successful remote database-backup receipt.
4. Preview the approved `install-plugin-package-v1` operation with activation
   enabled and overwrite disabled. Apply only after its confirmation gate.
   Existing inactive installations need separately reviewed activation;
   mismatched installed versions require an exact reviewed update.
5. Fresh-sync and require the Tokens main file to be active at the locked
   version. Verify its tree against the lock before full Fleet preflight.
6. Complete exact-package preflight, obtain a new remote backup receipt, then
   perform the separately authorized full Stack apply. A prerequisite write
   consumes its own receipt; never reuse it for the full apply.
7. Verify the runtime lock/hash, all required component trees, preserved child
   theme, administrator Tokens menu, custom-token save/reload and shortcode
   output. Confirm anonymous REST registry reads remain denied.

Missing Tokens must block full preflight until seeded; it is never an optional
upgrade or an implicit bypass of activation, backup or confirmation checks.

## Qualification status

Plugin source and focused functional QA are recorded with this release's
evidence. The existing local Stack runtime demonstrated escaped custom
shortcodes, connected business values, authenticated registry reads and denied
anonymous registry reads. Broad reference-site accessibility/performance
failures and the prior candidate's qualification gates remain rollout blockers
until the exact intended site passes its required checks.

Use `stack/MAINWP_FLEET_ROLLOUT_PLAN.md` for preflight, apply and retained
rollback. A generated package is preparation, not proof of deployment or a
declaration that Gloves Online is ready for production rollout.
